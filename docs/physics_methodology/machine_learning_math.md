# Machine Learning Architecture and the Masquerade Problem

The historical classification phase asks whether retained synthetic model
labels can be separated using macroscopic features
$X = \{M, R, \log_{10}\Lambda\}$. It does not deduce the internal composition
of a real star. In the reference sensitivity experiment, class identity remains
tied to the repository's analytic APR-1 surrogate and one fixed-CFL4 benchmark.

The exploratory models are extreme gradient boosting (XGBoost) and conventional
PyTorch multilayer perceptrons with dropout. The latter are not Bayesian neural
networks, and post-hoc sampling does not make their scores Bayesian posteriors.

### Confronting the Masquerade Problem
The broader masquerade problem motivates the synthetic comparison: distinct
dense-matter descriptions can produce overlapping macroscopic stellar
sequences. This repository does not establish that mass and radius are always
insufficient, or that one additional observable universally resolves that
problem. Its current family experiment instead finds that selected low-mass
radii separate the retained development catalogue, with a very small number of
independent final-test families.

The perturbation workflow injects a predeclared independent Gaussian noise law
into retained synthetic features. This is a sensitivity test, not a replica of
real NICER or LIGO inference: it omits posterior covariance, non-Gaussian
structure, source dependence, selection effects, and an astrophysical class
prior.

Any reported score or feature ranking must therefore remain limited to the
retained repository models, split design, and selected synthetic error law.
Neither the clean nor perturbed workflow proves phase-general discrimination,
observational readiness, calibrated composition probabilities, or a universal
need for tidal deformability. See
[`../CLASSIFICATION_RISK_AUDIT.md`](../CLASSIFICATION_RISK_AUDIT.md) for the
controlling risk assessment.
